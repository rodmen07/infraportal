## v1.20 - Proof integrity (DEFINED 2026-07-25; defaults apply unless the owner overrides)

**Why this is next.** The v1.16 to v1.19 themes and the NF-1 to NF-5 queue are shipped, and the frontend queue has since drifted into defect work: three of the last four increments were bug fixes, not capability. What was measurably broken is the one thing this site exists to do, which is carry PROOF. The platform came back on 2026-07-21, but the marketing surface was still telling the 2026-06-04 teardown story, including a headline stat tile reading **"$0 / Recurring infra cost today"** that had become FALSE: Cloud SQL `db-f1-micro` plus 10GB HDD is roughly $8 to $10 a month, and Artifact Registry grows by 11 images on every microservices merge with no retention policy. A visitor is ONE CLICK from `#/status`, which this repo now ships and which showed 11 services live on the probe above, so Home and the status board were contradicting each other in front of exactly the audience the funnel exists for. Meanwhile the repo README, the first thing a recruiter reads on GitHub, opened as "Task Portal Service" (verified 2026-07-25 by `head -1 README.md`), an identity retired two pivots ago. Slices v1.20.1 and v1.20.2 closed both, and v1.20.3 closed the third gap: the status board this repo had already shipped was reachable only by typing its hash, because the marketing nav deliberately excludes app surfaces and the site had no footer at all. **All three slices are shipped, so v1.20 is COMPLETE (2026-07-25). v1.21 is defined below (2026-07-26) and takes over from here.**

This milestone is therefore not new surface area. It is making the surface already shipped tell the truth, and guarding each claim so the class cannot rot again, the same shape as the guards shipped in PRs #83 and #84.

**Decisions (recommended defaults; "defaults approved" takes the lot, or override any single one).**

- **D-1, the teardown narrative.** DEFAULT: keep the teardown as the story but move it to past tense with the revival stated, for example "ran it to $0 once its job was done, then brought the Cloud Run half back for about $9 a month when the portfolio needed a live demo", and replace the `$0` tile with **"11 services live"** linking to `#/status`. Alternatives: (b) keep `$0` but re-label the tile to name the period it describes; (c) drop the cost framing entirely.
- **D-2, README identity.** DEFAULT: rewrite `README.md` to the current identity (consulting funnel, CRM demo portal, API playground, live status board; React 19 + Vite + TypeScript on GitHub Pages), keep one short dated history note for the Task Portal era, and link this roadmap. Alternative: a minimal one-paragraph banner correction that leaves the body alone.
- **D-3, where the status board lives.** Open since NF-1 PR2 and never answered. DEFAULT: add a persistent **site footer** carrying Status, GitHub, crates.io and Contact, and leave primary nav unchanged. Rationale: `src/features/layout/navItems.test.ts` records a deliberate decision keeping workspace and app items out of the marketing nav (its "should NOT include Status item" case), and this site has **no footer at all today**, verified 2026-07-25 by four searches that all came back empty: no `<footer>` element anywhere under `src`, no `Footer.tsx` in `src/components/` or `src/features/layout/`, zero occurrences in `index.html`, and the only three matches for the word "footer" in `src` are two code comments and one section label. ## v1.21 - Live proof (DEFINED 2026-07-26; COMPLETE 2026-07-26 — all three slices shipped, PRs #93, #94, #95)

**Why this is next.** v1.20 made the shipped surface TRUE. It did not make it ALIVE, and the QA pass that closed v1.20's last slice found the gap the moment it looked: a proof surface can be perfectly honest and still be **dead, self-throttling, or unguarded**. All three classes are on public case-study pages, i.e. exactly where a recruiter lands from the funnel, and every number below was measured on 2026-07-26 rather than inherited from the report that filed it.

1. **Dead.** `VITE_MONITORING_URL` is read by `deploy-pages.yml:59` as `${{ vars.VITE_MONITORING_URL }}`, but `gh api repos/rodmen07/infraportal/actions/variables` returns `total_count: 0`, so `src/config.ts` resolves `MONITORING_URL = ''` and the branch is constant-folded away at build time. `BuildStatusSection` and `PipelineMetrics` both take `phase: 'disabled'` and `return null`, which silently blanks a whole panel on **three** public pages: `#/case-studies` and `#/case-studies/cicd` (the "CI/CD Status" panel, rendered at `CaseStudiesPage.tsx:56` and `CicdCaseStudyPage.tsx:272`) and `#/case-studies/dynamodb` (the "Live Pipeline" panel at `DynamoDbCaseStudyPage.tsx:383`). Their intended backend was observaboard, which was destroyed in the 2026-06-04 teardown and now answers **404**, so this cannot be fixed by setting the variable.
2. **Self-throttling.** `useGitHubBuildStatus` runs `setInterval(load, 120_000)` (line 206) across the **7** repositories listed at `MicroservicesCaseStudyPage.tsx:331`, i.e. ~210 unauthenticated requests/hour against GitHub's **60/hour** limit, shared with everything else on the visitor's IP. A section headed "Live CI/CD" therefore guarantees its own degradation to "Unknown" after roughly a quarter of an hour on the page.
