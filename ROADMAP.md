Live endpoints are a legitimate verification target: features that read platform data may read the live gateway, and tests must not depend on the network (fixture the payload and cover the degraded/offline path).

## v1.20 - Proof integrity (DEFINED 2026-07-25; defaults apply unless the owner overrides)

**Why this is next.** The v1.16 to v1.19 themes and the NF-1 to NF-5 queue are shipped, and the frontend queue has since drifted into defect work: three of the last four increments were bug fixes, not capability. What is still measurably broken is the one thing this site exists to do, which is carry PROOF. The platform came back on 2026-07-21, but the marketing surface still tells the 2026-06-04 teardown story, including a headline stat tile reading **"$0 / Recurring infra cost today"** that is now FALSE: Cloud SQL `db-f1-micro` plus 10GB HDD is roughly $8 to $10 a month, and Artifact Registry grows by 11 images on every microservices merge with no retention policy. A visitor is ONE CLICK from `#/status`, which this repo now ships and which showed 11 services live on the probe above, so Home and the status board contradict each other in front of exactly the audience the funnel exists for. Meanwhile the repo README, the first thing a recruiter reads on GitHub, still opens as "Task Portal Service" (verified 2026-07-25 by `head -1 README.md`), an identity retired two pivots ago.

This milestone is therefore not new surface area. It is making the surface already shipped tell the truth, and guarding each claim so the class cannot rot again, the same shape as the guards shipped in PRs #83 and #84.

**Decisions (recommended defaults; "defaults approved" takes the lot, or override any single one).**

- **D-1, the teardown narrative.** DEFAULT: keep the teardown as the story but move it to past tense with the revival stated, for example "ran it to $0 once its job was done, then brought the Cloud Run half back for about $9 a month when the portfolio needed a live demo", and replace the `$0` tile with **"11 services live"** linking to `#/status`. Rationale: the full arc (build it, tear it down to $0 deliberately, revive it deliberately at a measured cost) is a stronger FinOps narrative than either half alone, and it makes the tile true and clickable rather than contradicted one click away. Alternatives: (b) keep `$0` but re-label the tile to name the period it describes; (c) drop the cost framing entirely.
- **D-2, README identity.** DEFAULT: rewrite `README.md` to the current identity (consulting funnel, CRM demo portal, API playground, live status board; React 19 + Vite + TypeScript on GitHub Pages), keep one short dated history note for the Task Portal era, and link this roadmap. Alternative: a minimal one-paragraph banner correction that leaves the body alone.
- **D-3, where the status board lives.** Open since NF-1 PR2 and never answered. DEFAULT: add a persistent **site footer** carrying Status, GitHub, crates.io and Contact, and leave primary nav unchanged. Rationale: `src/features/layout/navItems.test.ts` records a deliberate decision keeping workspace and app items out of the marketing nav (its "should NOT include Status item" case), and this site has **no footer at all today**, verified 2026-07-25 by four searches that all came back empty: no `<footer>` element anywhere under `src`, no `Footer.tsx` in `src/components/` or `src/features/layout/`, zero occurrences in `index.html`, and the only three matches for the word "footer" in `src` are two code comments and one section label. A footer buys discoverability without reopening the nav decision, and its absence is itself a gap a visitor notices. Alternative: a primary-nav "Status" item, which requires rewriting that guard.

**Slices. Each is one autodev increment: branch, PR, green gates.**

- **v1.20.1 - proof narrative truth (closes PROOF-COST-1).** Rewrite `src/features/site/ProofStrip.tsx` (narrative plus stat tile) and the "full lifecycle, including the shutdown" section of `src/pages/CaseStudiesPage.tsx` per D-1. **Done when:** the two `PROOF-COST-1` entries are gone from the allowlist in `src/features/site/runtimeStatusCopy.test.ts` and that suite is green. The allowlist is self-expiring by construction (each entry must still exist AND still make a claim), so the entries cannot be removed until the claims actually are. Plus a new assertion that bans a present-tense "$0 recurring" cost claim anywhere in `src/**`.
- **v1.20.2 - README identity truth pass (D-2).** **Done when:** `README.md` no longer presents "Task Portal Service" as the current identity, names the current one, and links `ROADMAP.md`; a new test asserts all three so the identity cannot silently rot again; and the History note at the bottom of this file is deleted in the SAME PR, because it exists only to warn about the stale README and would itself go stale the moment the README is fixed.
- **v1.20.3 - persistent site footer (D-3).** A real `<footer>` landmark rendered on every route, tokens only, keyboard reachable with a visible focus state, correct in both themes. **Done when:** the footer renders on every route; its `#/status` destination is checked against the router vocabulary parsed out of `src/main.tsx`, reusing the drift-guard pattern `src/features/layout/routeIntegrity.test.ts` already establishes; `navItems.test.ts`'s "should NOT include Status item" guard still passes untouched; and the token-integrity, type-scale-floor and opacity-coverage guards stay green, so no new raw palette class enters the tree.
